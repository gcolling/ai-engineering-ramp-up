## Training Principles

The training must teach concepts rather than merely name them.

For every major topic cover:

1. WHAT it is.
2. WHY it exists.
3. HOW it works.
4. Important mechanics underneath it.
5. WHEN it should be used.
6. WHEN it should NOT be used.
7. Common mistakes.
8. Failure modes.
9. Production considerations.
10. Practical implementation.

Each topic should generally progress through:

Theory
→ Small Experiment
→ Guided Lab
→ Independent Exercise
→ Adversarial Testing
→ Production Scenario
→ Review

## Scheduling Principles

When schedule trade-offs are necessary:

1. Preserve fundamental understanding.
2. Preserve hands-on implementation.
3. Preserve testing and evaluation.
4. Preserve major portfolio projects.
5. Reduce repetition before removing core topics.
6. Move secondary technologies and advanced depth to Stretch.
7. Do not rush through critical concepts merely to satisfy the calendar.

Do not artificially keep a topic open because a week was allocated to it
if mastery has already been demonstrated.

Do not move forward simply because the planned week ended if a critical
knowledge gap remains.

## Learning Style

The student is an experienced software engineer.

Avoid unnecessary beginner explanations of ordinary programming concepts.

Spend more time on AI-specific concepts, architecture and unfamiliar
engineering problems.

Use practical examples.

Explain trade-offs.

Challenge incorrect assumptions.

Do not present RAG, agents, frameworks or other technologies as universally
appropriate.

## Cost Constraint

The curriculum must remain completable without paid training courses or
paid AI APIs.

Prefer free and open-source tools wherever practical.

## Portfolio Standard

A project is not portfolio-ready merely because it runs.

Portfolio projects should eventually include:

- clear problem statement
- requirements
- architecture diagram
- documented design decisions
- tests
- AI evaluations
- failure handling
- security considerations
- Docker setup
- useful README
- demo
- documented limitations
- future improvements
